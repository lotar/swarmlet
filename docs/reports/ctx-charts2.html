What this run says

  • Decode is flat across 4K→256K (5.19–6.22 tok/s, deep probe) and worker free RAM falls as ctx grows: the worker pays for context, the decode rate does not.
  • Aggregate rises with concurrency and then saturates, while the per-caller rate falls; the two curves cross where concurrency x c1 stops being available, which is why the ask (c1's rate at every level) cannot be met by scheduling alone.
  • TTFT grows with concurrency - prompt processing and queueing, not decode - which is what the relayed ring would show if trips mattered more than compute; decode being flat across ctx says they do not.
  • Identical answers everywhere: every cell's output hash matches the reference 565339bc4d33, so none of this trades accuracy for speed.
