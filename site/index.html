01 / Mechanism

Bring hardware. Swarmlet builds the plan.

A 16 GB card can contribute without pretending it can hold the whole model. A slower node can add useful memory without being allowed to stall every token. The assignment changes with the actual mix.

01. Inspect

Inventory every node

VRAM, RAM, compute features, bandwidth, latency, availability, and trust signals.

02. Decide

Compare split strategies

Score stages, experts, tensor banks, or whole requests against the model graph and hardware limits.

03. Place

Keep every host in budget

Assign model parts and routes without relying on a secretly oversized coordinator.

04. Serve

Present one endpoint

Coordinate execution, reduce results deterministically, and remap work when a node leaves.

02 / Adaptive split

Different model. Different hardware. Different answer.

Swarmlet is architecture-neutral by design. The planner may choose one technique or combine several; it can also reject a split when network physics would make it worse.

A

Stage split

Place sequential blocks on nodes with enough memory and a fast link between them.

B

Expert split

Route sparse mixture-of-experts work only to the nodes that own the selected experts.

C

Tensor-bank offload

Move a bounded weight bank to a remote GPU or RAM tier while the main runtime coordinates.

D

Whole-request routing

Send complete requests between independent cells when the wide-area link is too slow for token-by-token work.

03 / Outcomes

Why connect the machines?

The aim is not distribution for its own sake. It is usable model capacity, useful speed, a home for idle hardware, and graceful survival when hardware disappears.

01

Fit larger models

Pool memory so one model can outgrow every individual card.

02

Use idle hardware

Let old and new machines contribute according to what they can safely do.

03

Add parallel capacity

Route independent work concurrently when the topology supports it.

04

Absorb failures

Detect departed nodes and produce a new placement instead of corrupt output.

04 / Physical proof

A consumer GPU has joined a real Qwen run.

The latest signed artifact is narrow but physical: Qwen3.8 Flash Next generated on an Apple Silicon host while a Legion laptop served a remote layer-0 fused expert bank over an SSH-forwarded GGML RPC path.

21.21

tokens / second

Measured decode speed for the GPU-only remote arm on a Legion GTX 1650 Ti. It matched the 64-token CPU baseline exactly.

1.68 GB

remote GPU memory used

The physical node loaded the bounded remote bank without swap growth; the owned processes were cleaned up afterward.

1 + 2

current physical network rig

One Mac and two Legion hosts are the active network test topology. The one-Legion Qwen path is signed; the separate two-owner protocol exists, while its signed physical result remains pending.

What this does not prove

It is not yet a full model split, true per-expert execution, an autonomous planner, or an anonymous public network. The current coordinator still holds responsibilities the finished cell must distribute.

06 / Product shape

Four surfaces. One orchestration layer.

Cluster owners, node contributors, and application developers meet the same system from different sides.

Node

Contribute hardware

Install an agent, publish measured capabilities, accept bounded assignments, and leave cleanly.

CLI

Operate a cell

Inspect nodes, profile models, generate plans, run proofs, and diagnose placement.

API

Serve applications

Send normal inference requests to one OpenAI-compatible endpoint.

Web

See the mesh

Watch capacity, assignments, model health, failures, and roadmap gates.

Network physics

A public mesh is a federation of complete cells.

Fast local links carry latency-sensitive model splits. Wide-area links carry whole requests between cells. Swarmlet should never hide a bad network path behind a bigger node count.
